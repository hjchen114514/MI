## What Failed / Known Issues

### Llama 3.2 3B — Too Slow on MacBook
- Model loaded fine but used ~13GB RAM (expected: float32 × 3B params = 12GB + buffers)
- Single session took >20 min on MPS — infeasible for 100 sessions
- **Fix for next attempt**: switch `model_loader.py` to `torch.bfloat16` (halves RAM to ~6GB, 2-3× faster on MPS). One line change in `model_loader.py`.
- Llama is the right model for the paper — SmolLM2 results are PoC only

### Youden's J Cutoff — SmolLM2 Artifact
- Empirical cutoff came out **19/20** (only choice=20 is AI-like)
- SmolLM2 base defaults almost entirely to 20, so boundary is degenerate
- Human-FT after fine-tuning almost never picks 20 → near-zero AI-like sessions → latent vector is degenerate → phase4 KDE fails with `LinAlgError`
- **Fix for next session**: hardcode cutoff back to **≤18 = human-like, ≥19 = AI-like** (matches Arad & Rubinstein 2012 literature and professor's paper). Requires relabeling script (does NOT require re-running model sessions — activations are already saved).

## Step 3/4 vs SAE — Decision

### Original Step 3 (Attention Patching) + Step 4 (Attention Heatmap)
- Causal story: layer K drifts → head H causes it → head H stopped reading strategic tokens
- Feasibility: high, results producible tonight
- Novelty: medium. Patching is solid MI (2022-era). Heatmaps are the weakest link (2019-era, criticized as insufficient)

### SAE (Sparse Autoencoder)
- Feasibility: risky with only 100 sessions — SAEs need large activation corpora to learn meaningful features
- No pre-trained SAEs available for SmolLM2-360M; Llama 3.2 3B support via `sae-lens` is partial
- Time to implement properly: days not hours
- Novelty: high — "latest MI methods", would impress DK

### Decision: Do Both In Sequence
**Tonight**: fix cutoff → phase3/4 → get layer K + head H → send DK brief email with KDE plots
**Weekend**: implement SAE on layer K activations
**Monday**: present full story to DK

**Combined storyline:**
> "We identify the corrupted layer K via residual stream probing (Cohen's d). We then identify the responsible attention head H via activation patching (JSD reduction). Finally, we train a sparse autoencoder on layer K activations to characterize *what* was disrupted — human_ft sessions activate strategic backward-induction features, doped_12x9_ft suppresses these and activates generic pattern-completion features."

**Practical SAE plan:**

| | SmolLM2-360M PoC | Full Research |
|---|---|---|
| Model | SmolLM2-360M | **Llama 3.1 8B Instruct** (not 3.2 3B) |
| SAE | Train custom from scratch | Load pre-trained from sae-lens (8 SAEs available) |
| Sessions needed | 500 (for SAE training corpus) | 100 standard |
| Training time | ~30 min total on MacBook | No training — just load + apply |
| Hardware | M4 MacBook fine | Needs 24GB+ RAM (bfloat16 = ~16GB) |

**Note: switch full research model from Llama 3.2 3B → Llama 3.1 8B Instruct.** sae-lens has no pre-trained SAEs for 3.2 3B but has 8 for 3.1 8B Instruct. This is a significant advantage — no SAE training needed for the full research run.

**SmolLM2 SAE training steps:**
- Run 500 sessions on human_ft at layer K → collect 500×960 activation vectors
- Train SAE: dictionary size ~3840 (4× residual dim), L1 sparsity penalty
- Freeze trained SAE, encode doped_108_ft and doped_12x9_ft activations through it
- Compare: which features are dead/suppressed in each doped condition vs human_ft?

**Key paper**: Anthropic "Towards Monosemanticity" (2023)
**Key library**: `sae-lens` (pip install sae-lens) — pre-trained SAEs for Llama 3.1 8B Instruct confirmed
